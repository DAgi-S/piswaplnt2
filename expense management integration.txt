# Task: Integrate Expense Management Feature to Existing System

## 🎯 Objective:
Integrate a new module called "Expense Management" into our existing PHP + MySQL system **without altering** existing tables, data, or structure. All new files must live under a **new folder called `expense/`**.

---

## 🛠️ System Constraints and Guidelines

1. ✅ Do NOT modify any existing database tables or application logic.
2. ✅ Check if any expense-related tables already exist (e.g., tables with names like `expense`, `expenses`, `expense_entries`, etc).
3. ✅ If not found, create new expense-related tables using the most logical structure (with `expense_categories`, `expenses`, etc).
4. ✅ Respect our permission system: integrate `user_roles`, `permissions`, `roles_permissions` where needed (add new permission keys only, no deletions).
5. ✅ Implement full CRUD (Create, Read, Update, Delete) for expense entries.
6. ✅ Add proper routing, controller logic, models, and views inside `expense/` folder.
7. ✅ Make sure **no admin privileges are required**, as we’ve had MySQL hosting issues with restricted access.
8. ✅ Keep SQL structure safe for shared-hosting environments (no use of `DEFINER`, `PROCEDURE`, etc).
9. ✅ Keep code DRY, reusable, and aligned with the current project’s coding style.

## ⚠️ Hosting Notes (Must Avoid)
We have **limited privileges on the hosting server**. So:
- ❌ No `DEFINER` procedures
- ❌ No `SIGNAL`, `DECLARE`, or stored procedures
- ✅ Use only pure `INSERT`, `UPDATE`, `SELECT` MySQL queries inside PHP
- ✅ Do not drop or alter existing tables or constraints

## ✅ Final Notes
- Make everything modular and isolated.
- Register expense-related permissions (e.g., `create_expense`, `edit_expense`, `view_expense`, `delete_expense`) and integrate with our permission system.
- Always check for session permission using the global `can('permission_key')` function before allowing access.
