## Notes
1. Super Admin (roleId = 1) and Admin (roleId = 2) have implicit access to all permissions
2. Some permissions are module-specific and may require additional related permissions to function fully
3. Permissions are organized by modules for better management
4. Some permissions may have dependencies (e.g., edit permission may require view permission)

## Database Structure
The permission system uses these tables:
- permissions: Stores all available permissions
- role_permissions: Maps roles to permissions
- user_roles: Maps users to roles
- roles: Defines available roles
- user_permissions: (if exists) Stores user-specific permission overrides

## Best Practices
1. Always check permissions before performing sensitive operations
2. Use the most specific permission possible
3. Combine role-based and permission-based checks for better security
4. Keep permission names consistent with the naming convention
5. Document new permissions when adding features

## Managing Permissions
Administrators can manage permissions through:
1. Role Management interface
2. User Management interface
3. System Configuration
4. Direct database access (for system administrators)
