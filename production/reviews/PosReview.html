Point of Sale (POS) Module Review

1. Module Overview

1.1 Module Location

The POS module is located in the production subsystem with the following key files:

  • production/pos.php - Main POS interface
  • production/custom/js/pos.js - Core POS functionality
  • production/custom/js/pos_cart.js - Cart management
  • production/custom/js/pos_print.js - Receipt printing functionality
  • production/php_action/createPOSOrder.php - Order processing backend
  • production/php_action/fetchPOSProducts.php - Product data retrieval

1.2 Module Purpose

The POS module serves as a comprehensive point-of-sale system with the following primary objectives:

  • Real-time product inventory management
  • Sales transaction processing
  • Receipt generation and printing
  • Client management
  • Integration with the production system for stock updates

7.2 Payment Processing Flow

  1. Payment Initiation
    • Validate payment amount against remaining balance
    • Capture payment method (Cash, Bank Transfer, Check)
    • Record reference number and notes if applicable
  2. Transaction Recording
    • Insert payment record in sales_payments table
    • Update order's paid_amount and balance
    • Update payment_status (unpaid/partial/paid)
  3. Status History
    • Record payment status change in sales_status_history
    • Track payment method and reference information

7.4 Payment Status Types

Status Description Conditions

Paid Fully paid paid_amount = total_amount

8. Payment Initiation Deep Dive

8.1 Initial Payment Flow in createPOSOrder.php

Entry Point: When a POS sale is completed, the payment process starts in createPOSOrder.php

  1. Transaction Initialization
    • Begins with a database transaction to ensure data consistency
    • Validates user session and authorization
    • Checks for duplicate transaction IDs
  2. Order Creation
    • Generates unique order number (format: POS-YYYYMMDD-XXXX)
    • Records initial order details in sales_orders table
    • Sets initial payment status as 'unpaid'
  3. Payment Recording
    • Records payment details if immediate payment is made
    • Updates order's payment_status based on payment completion
    • Possible statuses: 'unpaid', 'partial', 'paid'

8.3 Transaction Safety Measures

  • Database Transaction Handling
    • Begins transaction before any database operations
    • Commits only after all operations succeed
    • Rolls back on any error to maintain data integrity
  • Validation Checks
    • Verifies user authentication and authorization
    • Validates payment amount against order total
    • Checks for duplicate transaction IDs
    • Validates product stock availability

8.4 Stock Management Integration

  • Automatic stock updates in both tables:
    • Updates production_products.current_stock
    • Updates products.current_stock
    • Validates stock availability before processing
  • Rollback Protection
    • Stock updates are part of the transaction
    • Reverts stock changes if payment fails
    • Maintains stock integrity across the system
